Where the data comes from

This script uses LegiScan, a legislative-tracking service, to supply details from the full text about state policies on cell phone use and sorts them into passed, in progress, and failed categories. It then cross-checks with NCSL (the National Conference of State Legislatures) and Ballotpedia to ensure accuracy.

How often it updates

A script runs automatically through GitHub Actions once a day at 11:00 UTC, pulling fresh data from all three sources above and rewriting the site's data file if anything has changed. This is independent of any one person — nobody needs to manually refresh or edit anything for the tracker to stay current.

What the four categories mean

PermittedState law explicitly allows a software or technology-based approach.
AmbiguousA restriction law exists but doesn't specify a method — could be read either way until a district writes its own policy.
No LawNo statewide legislation. Entirely up to individual districts.
RestrictedA hard, physical-storage mandate (pouches, lockers, etc.) is in place — incompatible with a software-only approach.

How a state gets classified

The script reads the actual bill or summary text for each state and looks for specific language: words like "pouch," "locker," or "stored off their person" signal a hard physical mandate, while words like "app," "software," or "device management platform" signal a law that's explicitly friendly to a technology approach. It also checks the wording immediately around each match, so "lockers are not permitted" isn't mistaken for a mandate, and "students may use a locker as one option" is treated as optional rather than required. It also recognizes when physical storage is listed as one example among several ("acceptable methods include lockers, pouches, or backpacks") rather than a requirement, so a law that leaves the method up to each district doesn't get misread as a mandate just because a pouch is mentioned somewhere in the text. When the wording doesn't clearly match any of these patterns, the state is marked Ambiguous rather than guessed.

If LegiScan finds a bill that's already passed but NCSL and Ballotpedia haven't listed it yet, the script fills that gap automatically rather than waiting on those sources to catch up, and flags it on the site as auto-detected until they do. A small number of states also carry a manually verified correction, used when someone has checked a state's real-world policy against a primary source and confirmed or fixed what the automated read produced. Those corrections don't re-check themselves, though - each one is tied to the specific bill it was researched against, and if that state's bill on record changes, the site flags the correction as possibly outdated (visible as a warning badge on that state) rather than silently continuing to trust it forever.

In-progress and failed bills

Any bill still moving through a state legislature, or one that has already failed, appears in that state's detail view with a summary of how it would impact Doorman if passed.

A note on accuracy

This tracker is auto-generated from primary legislative sources, not hand-curated, so treat it as a well-informed starting point rather than a legal opinion. If something looks off for a specific state, it's worth checking the bill link directly — and any correction can be added as a permanent, documented override so the fix sticks on every future update.
